## Agent workflow and execution

1. Read [AGENTS.md](AGENTS.md), [docs/PROJECT.md](docs/PROJECT.md), and this file before selecting cases. Use [docs/LOCAL_TESTING.md](docs/LOCAL_TESTING.md) for environment setup. Keep this root file as the detailed single-file checklist for future runs.
2. Select relevant automated and browser cases below. Add every new or changed automated/manual case definition to this same file, preserving stable IDs, steps, expected results and executable source paths where applicable. Keep existing assertions in `server/*.test.js`; implement new automated coverage there and update its catalog entry in the same change. This Markdown does not replace or execute the JS tests.
3. Use Node.js 22 or newer. Install with `npm ci` when dependencies are missing or the lockfile changed. Run focused checks during development, then the full report and build after behavior/UI changes when source has settled. Documentation-only changes need content, inventory, and link checks.
4. For multiplayer work, also use at least two independent browser sessions; use three/four distinct authenticated seats to exercise a full party table. Duplicating a tab can copy its private seat credential. Automated Socket.IO clients are valuable evidence but do not replace browser interaction or layout checks.
5. Record actual results and untested variants in the existing reports. Do not mark this entire catalog passed based on a suite, build, old screenshot, or remembered result.

From the project root:

```sh
# Full automated run with saved results:
npm run test:report

# Example focused run (does not replace the full report):
npm run test:report -- server/localGame.test.js server/setupDefaults.test.js

# Equivalent full suite without the report wrapper:
npm test

# Frontend compilation, separate from test execution:
npm run build
```

`npm run test:report` discovers `server/*.test.js`. Full runs write `reports/tests/latest.md` and `.json`; focused runs write `reports/tests/latest-focused.md` and `.json`. The runner records scope, names, timestamps, Node version, totals and source/artwork fingerprints. Failed, incomplete, or source-changed runs do not pass. An inability to bind loopback sockets is an environment blocker; report it separately from assertion failures.

Use isolated test origins, disposable names and in-memory servers or temporary persistence files. Do not clear the owner's browser storage or change private saved rooms. The owner's **http://127.0.0.1:5179/** preview and backend on **3006** must remain running; only clean up disposable QA processes. Do not reuse old historical QA port assignments without checking current ownership. `npm run dev:5179` is the owner's restart command, not a request to launch a duplicate. Normal development uses `npm run dev` on 5173/3001. No packaging or publication is part of catalog maintenance.
